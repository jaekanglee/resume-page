바로고 | 2022.05 ~ 현재

팀원 · Android Native / Flutter 메인 개발자

콜 수 기준 배달대행 업계 1위 플랫폼의 라이더앱 담당. 최대 4명 규모 모바일 팀에서 바로고 도메인을 오래 다뤄 온 동료와 Native·Flutter 앱을 함께 개발했고, 아키텍처와 개발 방식은 주로 본인이 맡음. 세 앱의 PR을 서로 리뷰(본인 리뷰 685건). 회사 채용 블로그 직무 인터뷰에 소개됨.

기술: Kotlin, Java, Coroutines·Flow, Hilt, OkHttp·Retrofit, Socket.IO, Kotest·MockK·Robolectric, Fastlane · Flutter(Dart, GetX, freezed, MVI)

라이더앱 · Android Native | 2022.05 ~ 2025.12

과거 일 최대 70만 콜을 처리한 배차 플랫폼의 라이더앱 · v4.6.3~v6.21.4 61개 버전 릴리즈 담당 · Crash-free Users 99.89%·ANR-free Sessions 99.97% 수준으로 운영

  • 구조: Clean Architecture(domain·data·presentation) + MVVM, Hilt, Coroutines·Flow 기반 Kotlin 멀티모듈. 기존 Java 모듈에서 Lombok과 Kotlin이 충돌해 신규 코드를 별도 모듈에 쌓고, 레거시 Activity를 Hilt 진입점 삼아 구·신 구조를 공존시킨 뒤 3년 만에 모듈 통합(2025.07). 레거시 프로시저 호출은 동료와 나눠 REST로 이관(호출 메서드 98 → 37개). Gradle을 Kotlin DSL·Version Catalog로 옮기고 모듈 공통 설정을 buildSrc 플러그인으로 묶음
  • 중복 출금: 버튼 중복 터치와 약전계 재전송으로 같은 출금 요청이 여러 번 들어가 수수료가 이중 차감되는 장애가 운영에서 세 번 재발. 버튼 중복 입력 방어 → 동료가 제안한 자동 재시도 해제를 출금 전용 OkHttp 클라이언트로 분리 적용 → 같은 timestamp 요청이 다시 여러 건 들어오자 동시 요청 1건 제한. 이후 같은 장애는 재발하지 않음
  • 실시간 주문 목록: 소켓 패킷과 Socket.IO 푸시가 한 화면의 주문 목록을 함께 갱신하는 구조에서 QA 보고와 Crashlytics로 들어온 목록 크래시, 새 접수 미반영, 지도배차·접수목록 불일치를 이슈 단위로 추적. 네 목록이 함께 쓰던 어댑터·뷰홀더(약 800줄)를 목록별로 나누고, 화면 재생성 뒤 끊기던 패킷 처리부의 화면 참조를 바로잡음
  • 주문 선점 매크로: 접근성 클릭 차단 → '앱 위에 그리기' 터치 차단으로 대응했지만 리패키징·후킹으로 클라이언트 검사가 계속 뚫려 판단을 서버로 옮김. 서버 개발자와 나눠 앱은 Play Integrity 토큰을 받아 서버로 보내고 서버는 검증을 맡았고, 로그인 단계에서는 정상 라이더를 오탐으로 막지 않도록 차단 대신 실패 사유를 기록. 이후 서버가 소켓으로 보낸 nonce로 앱이 토큰을 만들어 회신하는 구조로 바꿈(2024.08)
  • 지도 화면 메모리 누수: 지도 화면을 오가면 나던 OOM·지도 SDK 중복 생성 크래시를 Crashlytics에서 확인하고, Profiler 힙 덤프로 종료 뒤에도 남는 Activity를 찾아 Context·MapView 내부 참조를 해제 시점에 정리. QA와 단말별 메모리 회수를 확인했고, SDK 내부 누수로 남던 검은 화면은 SDK v2 교체(2024.04) 뒤 재현되지 않음
  • OS·정책 대응: targetSdk 30 → 35 상향을 네 차례 맡아 PendingIntent·exported·알림 권한·뒤로가기·위치 포그라운드 서비스 타입 변경을 반영하고, 16KB 페이지 크기에 맞춰 네이티브 라이브러리가 든 SDK를 교체
  • 테스트·배포: 로그인·인증·출금 한도·추천배차 등 Kotest·MockK 도메인 테스트(약 144케이스)와 Hilt·Robolectric 통합 테스트(약 39케이스)를 작성하고, push 전 pre-push 훅과 Fastlane 배포 자동화(QC·Staging App Distribution, Play 내부 테스트, Slack 알림)에서 도메인 테스트를 먼저 돌림

허브관제앱 · Flutter | 2026.03 ~ 현재

허브·총판 관리자용 실시간 배달 관제 앱 · 2026.09 정식 출시 · 2인 팀에서 아키텍처·지도/목록관제·소켓 담당(동료는 주문 상세·대리 접수·관리 화면)

  • 폴링 → 실시간: 기존 관제앱의 7초 폴링이 만들던 중복 처리·콜 누락을 없애려 기획부터 출시까지 주도해 Socket.IO 기반으로 새로 만들고, 재연결 때는 REST로 재동기화. 조회 응답이 푸시보다 늦게 와 한 주문이 두 목록에 남던 문제는 '한 주문은 한 그룹' 규칙과 재현 테스트로 막음
  • 지도 ANR: 15분간 주문 푸시 796건 중 고유 이벤트가 99건뿐인 중복 수신과 마커 전체 속성 재기록이 원인. 동일 스냅샷 제거, 바뀐 속성만 반영하는 diff 렌더러, 이벤트 coalescing으로 플랫폼 채널 호출을 줄임
  • AI 결과물 검증: MVI(freezed 단일 State) 구조를 AI 코딩 에이전트가 따르는 팀 공통 지침·구조 검사기로 만들어 Flutter 라이더앱에도 적용하고, UseCase 테스트 407케이스를 pre-push에 연결

라이더앱 · Flutter | 2024.06 ~ 현재
