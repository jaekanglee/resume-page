요약

배달 플랫폼의 라이더앱과 관제앱에서 소켓·푸시·REST가 같은 화면을 갱신할 때 생기는 불일치와 장애를 원인부터 찾아 고쳐 왔습니다.

  • 실시간 데이터 정합: 주문 목록 불일치, 중복 이벤트, 재연결 뒤 누락을 로그와 코드로 좁혀 고침. Flutter 앱에서는 소켓 재연결과 주문 캐시 규칙을 재현 테스트로 확인
  • 운영 중 구조 전환: 배포를 멈추지 않고 Java 단일 모듈 라이더앱을 3년에 걸쳐 Kotlin 멀티모듈로 옮김
  • 돈과 보안이 걸린 경로: 중복 출금과 주문 선점 매크로를 QA·서버 개발자와 역할을 나눠 단계적으로 대응
  • 검증하는 개발: 도메인 테스트를 배포·push 조건으로 두고, AI 코딩 에이전트가 만든 코드는 팀 공통 구조 검사기와 같은 테스트로 검증

경력

바로고 | 2022.05 ~ 현재

팀원 · Android Native / Flutter 메인 개발자

콜 수 기준 배달대행 업계 1위 플랫폼의 라이더앱 담당. 과거 일 최대 70만 콜을 처리한 배차 플랫폼에서 Native 라이더앱(2022.05~2025.12)을 Crash-free Users 99.89%·ANR-free Sessions 99.97% 수준으로 운영했고, 2026년부터 Flutter 라이더앱과 신규 허브관제앱을 맡음.

최대 4명 규모 모바일 팀에서 바로고 도메인을 오래 다뤄 온 동료와 Native·Flutter 앱을 함께 개발하며 아키텍처와 개발 방식은 주로 본인이 맡았고, 세 앱의 PR을 서로 리뷰(본인 리뷰 685건). 회사 채용 블로그 직무 인터뷰에 소개됨.

기술: Kotlin, Java, Coroutines·Flow, Hilt, OkHttp·Retrofit, Socket.IO, Kotest·MockK·Robolectric, Fastlane · Flutter(Dart, GetX, freezed, MVI)

라이더앱 · Android Native | 2022.05 ~ 2025.12

  • 실시간 주문 목록 정합: 소켓 패킷과 Socket.IO 푸시가 한 화면의 주문 목록을 함께 갱신하면서 생긴 목록 갱신 중 크래시, 새 접수 미반영, 지도배차·접수목록 불일치를 이슈 단위로 추적. 네 목록이 함께 쓰던 어댑터·뷰홀더(약 800줄)를 목록별로 나누고, 화면 재생성 뒤 끊기던 패킷 처리부의 화면 참조를 바로잡음. 배차 대기 시간은 단말 시각 조작과 시각 오차에 흔들리지 않도록 SNTP로 보정한 네트워크 시각으로 판정
  • 멈출 수 없는 서비스의 구조 전환: 기존 Java 모듈에서는 Lombok과 Kotlin이 충돌해, 신규 코드를 별도 Kotlin 모듈에 쌓고 레거시 Activity를 Hilt 진입점 삼아 구·신 구조를 공존시킴. 레거시 프로시저 통신은 동료와 기능을 나눠 REST로 옮겼고, 3년 뒤 Lombok 제거와 모듈 통합까지 마침(2025.07, 1,530파일). Java 5.9만 → 3.9만 줄, 프로시저 통신 메서드 98 → 37개
  • 중복 출금: 수수료가 이중 차감되는 중복 출금이 운영에서 세 번 재발. 버튼 중복 입력 방어, 동료가 제안한 자동 재시도 해제를 출금 전용 OkHttp 클라이언트로 분리 적용, 동시 요청 1건 제한을 차례로 넣은 뒤 같은 장애는 재발하지 않았고 출금 오류도 로그로 추적
  • 주문 선점 매크로 대응: 접근성 클릭 차단 → '앱 위에 그리기' 터치 차단으로 대응했지만 리패키징·후킹으로 클라이언트 검사가 계속 뚫려 판단을 서버로 옮김. 서버 개발자와 나눠 Play Integrity를 붙였고, 로그인 단계 검증에서는 정상 라이더를 오탐으로 막지 않도록 차단 대신 실패 사유를 기록. 이후 서버가 소켓으로 보낸 nonce로 앱이 토큰을 만들어 회신하는 구조로 바꿈(2024.08)
  • 안정성·배포: Activity·MapView 누수와 화면 종료 뒤에도 남던 소켓 연결을 정리하고, Crashlytics와 통신 인터셉터로 오류를 추적. Kotest·MockK 도메인 테스트를 Fastlane QC·Staging 배포와 pre-push의 선행 조건으로 운영

허브관제앱 · Flutter | 2026.03 ~ 현재

허브·총판 관리자용 실시간 배달 관제 앱 · 신규 구축 · 2인 팀 · 2026.09 정식 출시

  • 실시간 관제 정합: 기존 관제앱의 7초 폴링이 만들던 중복 처리·콜 누락을 없애기 위해 기획부터 출시까지 주도해 Socket.IO 기반으로 새로 만듦. 재연결 때 REST로 재동기화하고, 조회 응답이 푸시보다 늦게 와 한 주문이 두 목록에 남던 문제는 '한 주문은 한 그룹' 규칙과 재현 테스트로 막음. 주문 캐시 반영 규칙은 정책 객체로 분리(테스트 19건)
  • 지도 ANR: 15분간 주문 푸시 796건 중 고유 이벤트가 99건뿐인 중복 수신과 마커 전체 속성 재기록을 원인으로 확인. 동일 스냅샷 제거, 바뀐 속성만 반영하는 diff 렌더러, 이벤트 coalescing으로 플랫폼 채널 호출을 줄임
  • AI 에이전트 개발 기준: 이 앱의 구조를 AI 코딩 에이전트가 따르는 팀 공통 지침과 구조 검사기(레이어 의존·단일 State 검사)로 만들어 Flutter 라이더앱과 함께 적용하고, UseCase 테스트 407케이스를 pre-push에 연결

라이더앱 · Flutter | 2024.06 ~ 현재

  • 2024.10 iOS 출시 막바지 QA에 합류했고, 2026년부터 메인 개발
  • 소켓 계층 재작성: 중복 연결 요청 때문에 서버가 중복 접속으로 판정하고, 재연결 20회 제한 때문에 음영 지역을 지난 뒤 영구 단절되던 소켓 계층을 다시 씀. 연결 주체를 하나로 모으고 횟수 제한 없는 backoff를 넣어 가짜 서버 재현 테스트로 확인한 뒤 v2.17.2(2026.10)로 배포. 최근 앱 목록에서 앱을 지울 때는 Dart 실행이 보장되지 않아, Android Service(onTaskRemoved)·iOS applicationWillTerminate에서 네이티브 코드가 퇴근 요청을 직접 전송
